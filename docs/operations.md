# 日常操作与维护

线上地址：[想看清单](https://austinzheguo.github.io/wishlist/)。网页由 GitHub Pages 托管，数据保存在 Supabase；当前采用**公开可编辑**模式，不需要登录。

## 日常使用

- 添加、编辑、删除以及导入后，右上角会显示“等待同步”“正在同步”或“已同步”，并显示最近一次成功同步时间。看到“同步失败”时，修改仍保存在当前浏览器；恢复网络后点击“重试同步”。
- 删除条目后，底部会出现 60 秒倒计时的“撤销删除”按钮。撤销会把原条目恢复并同步；倒计时结束后，删除按正常结果保留。刷新网页不会提前取消仍在倒计时内的撤销入口。
- 如果显示“发现跨设备冲突”，表示另一台设备或页面已先更新云端。网页已停止自动覆盖：先点击“处理冲突”下载本机修改备份，再选择“读取最新版云端”。本机冲突备份会保留到你完成该操作。
- 即使有冲突提醒，仍建议在切换设备前等待“已同步”。该功能防止意外的旧页面覆盖，不能阻止公开模式下第三方故意修改清单。
- 每月一次、以及调整数据库权限前，在网页右上角点击“导出备份”，将 JSON 文件至少保存在本机和一个云盘位置。

## 更新网页

正式源码在本仓库的 `index.html`。修改与发布流程：

1. `git pull` 获取最新版本。
2. 修改并在本地测试；不要直接编辑旧资料目录里的 `wishlist.html`。
3. 用 `git diff` 核对改动，然后提交并 `git push`。
4. 等 GitHub Pages 部署完成后，用无痕窗口打开线上地址确认。

## 数据库迁移记录

`supabase/003_add_wishlist_revision.sql` 是 v1.1.0 的一次性迁移：为 `wishlist_data` 增加 `revision` 版本号，以支持跨设备冲突检测。它不改变当前公开访问策略，也不会改写清单内容。

`supabase/004_normalize_wishlist_items.sql` 是 v1.4.0 的结构迁移：将清单拆成 `wishlist_items` 逐条记录，并保留 `wishlist_data` 作为兼容快照和回退备份。前端通过 `replace_wishlist_items` 做带版本校验的事务同步。当前公开模式的访客权限暂未收紧，后续如要改为“只能新增”，应另行设计只追加接口或待审核表。

## 安全与恢复密码

公开模式意味着知道网址的人都能查看、添加、编辑和删除这份清单。Supabase 的 publishable key 可以公开，但绝不能把 `service_role`、secret key、数据库密码或账号密码写入仓库。

如需重新启用密码访问，请按 [public-mode.md](public-mode.md) 的“以后恢复密码”部分操作；恢复前先导出一份备份。
